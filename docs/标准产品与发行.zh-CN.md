# 标准产品与组合发行

产品分为共享平台、虚拟化与资源调度、持久存储、控制面与认证访问、业务运行时五层。数据面不能独立代替控制面 Operation，Helm 也不能代替原生资源所有者。核心部署关系与微服务图统一维护在 Helm 标准文档。

Neon 组合发行必须固定 Autoscaling、Control Plane、Helm 和 PostgreSQL 来源。构建与发布程序先检查 `ci/distribution.json` 及复用工作流一致性；新依赖需先提交推送，再更新本仓库。不得仅把 Helm 改为分支最新而继续调用旧 SHA 的复用工作流。

公开 GitHub 构建发布与内网运行是两个阶段。内网 Harbor 地址、项目及节点拉取信任是站点配置，不写死为某台服务器。镜像搬运应保留原始摘要；镜像内容变化必须产生新摘要、来源和验证记录。旧镜像的基线与补丁不能追认成后来提交的完整可重现构建。

实际验收使用公开控制面创建、Proxy 校验身份的 SQL、同一 Compute 的 Guest 物理内存往返、原数据、WAL 结清、暂停恢复和退役；源码检查和合成测试不能替代这些事实。历史验收按当次源码与摘要保留，不改写成新发行的现场证明。

不依赖公网 IP、域名或外网控制面。内部证书和 DNS 服务仍需正确配置；省略公网入口不等于关闭内部身份验证。新 Node 连续接入、生产 HA、完整 TLS 与灾备不在本轮范围。
