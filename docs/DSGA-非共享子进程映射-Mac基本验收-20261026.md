# 非共享子进程的DSG映射寿命与Mac验收

本模块对应V3 R01/R02/R05的进程引用边界，不代表完整VM缩容已经实现。
PG17修复 `b812536cd983595ba233a7fad418d9bae448b2f3` 已先推自有既有
`codex/dsga-pg17-v3-20261019` 并核验远程；Neon继续原
`codex/dsga-neon-v3-20261019`，不改主分支、不重建分支、不强推。

## 实际缺陷与修复不变量

旧准确PG5462独占进程的真实Mac vmmap显示：Postmaster、持久协议backend与
logger均持有四个DSG共享映射，共67,928,064字节。logger的RSS为0不能证明
backing引用消失；logger会跨同Postmaster内部共享内存重建存活，从而保留旧映射。
原官方`dsm_detach_all/PGSharedMemoryDetach`只处理DSM和主段，不含新增四数组。
旧版本现场及解析校验保留，旧5462安装目录和库不覆盖。

PG17当前`child_process_kinds`只有B_LOGGER的shmem_attach=false；业务、恢复、
维护与BG worker的共享内存路径保持原行为。新函数在非共享子进程Main前、主段
脱离之前解除当前进程的四数组，父进程退出/重建回调复用同一函数。几何在boot
内不可变，无PGPROC，不取backend锁。必须销毁局部DsgRegion副本：目录属于
MAP_SHARED，直接对目录调用Destroy会MemSet所有进程仍在使用的共享几何。
仅清当前进程全局别名，不改共享状态/成本/占用/未知标记，不改父进程回调。
munmap错误沿原ERROR/退出处理，不能进入无共享内存的Main声称已安全脱离。

Buffer6/Work2/Connection1/Prepared1/DSM1布局和Neon扩展1.15均不改变；不改
WAL、PG配置或缓冲算法。新增双SU测试专用VA/span getter只读真实几何，不是
公开业务接口，也不提供物理释放、预算或VM许可。

## 本次实际Mac验证

新增三个不同真实场景全部通过、0skip：首次logger、Grow256→512后只杀当前
owned logger并确认自动重建、新旧boot期间logger同PID持续存活。每次先证
父/backend完整四数组共享覆盖，再接受logger不存在共享重叠；同时验证目录
没有被子进程清零，真实表count/sum/hash不变。持久backend PID取自实际
BackendKeyData，不猜psql短连接。只操作本次独占临时PG进程。

候选编译标记明确为nonshmem-candidate-dirty；不是准确发布SHA。提交后另用
新安装目录重建准确完整SHA、配套test_dsg_region/neon_rmgr及Neon1.15；首次
与内部崩溃两个关键场景按准确制品替换验证，不把它们加计为五个不同测试。
准确制品结果以同名机器收据为准。未变DSM8/core225/iso123/Go33不重复执行。

可复现核心命令（路径替换为实际安装根）：

```sh
export NEON_TEST_PG_BIN=/absolute/exact-prefix/bin
export NEON_TEST_DSG_LIBRARY=/absolute/exact-prefix/lib/postgresql/test_dsg_region.dylib
export NEON_TEST_RMGR_LIBRARY=/absolute/exact-prefix/lib/postgresql/neon_rmgr.dylib

cd ci
python3 -m unittest test_dsg_nonshmem_child -v
```

Mac实测使用/usr/bin/vmmap。Linux /proc/PID/maps读取分支已编写但未在目标
环境执行；内核共享映射/真实物理回收、cgroup/HugeTLB/性能仍需后续Linux验收。
本批没有构建镜像、准备/执行K8s部署，不用Mac替代目标环境认证。
