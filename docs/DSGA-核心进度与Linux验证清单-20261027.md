Host资源退还分别是不同事实，必须逐层获得真实回执，不按Mac结果推断后两项。

## 固定收尾顺序与加速约定

1. 每个可独立验收的模块先完成代码、Mac受影响测试及中文说明，立即提交并
   推送现有自有分支；先依赖autoscaling，后Neon依赖锁，PG17保持准确gitlink。
2. 按前表已有缺口闭合：部分效果取消；可信预算/首次服务；异常生命周期；
   持续控制和策略。不增加独立控制面或其他PG版本，不逐批追新上游。
3. 用同一次组合覆盖成功、丢回复、重建、来源漂移及结清；保留每个采用场景
   对应日志。仅新增/变化/受影响功能重跑，已通过且未改PG/Rust不重复。
4. Mac不做目标平台认证；Linux再执行上表。当前不构建镜像、不准备/执行部署，
   不合main。阶段提交不等于整体完成，报告须保留所有尚缺代码。

这个顺序压缩重复编译/测试与维护噪声；真实尚缺实现必须继续完成，不能通过
删除失败用例、降低来源/身份检查或改写状态缩短流程。
