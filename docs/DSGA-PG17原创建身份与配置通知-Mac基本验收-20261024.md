# 原创建身份与配置通知：Mac 基本验收

## 问题与行为

此前初始化回执直接回显当前 spec.operation_uuid，而官方存储位置/configure 通知可以更新它。同一 PG/Compute/tenant/timeline 没有改变时，原创建控制面仍会因 UUID 不同拒绝对账。另一方面，运行中 configure 只比较启动预算，未明确拒绝改绑另一 tenant/timeline。

本批在 Compute 首次接受的可信启动规格中冻结原 operation_uuid、解析后的 tenant/timeline。有初始规格时在构造时冻结，空闲 Compute 在首次启动接受规格时冻结；OnceLock 不因重配或重试覆盖。解析后身份兼容官方旧 GUC 表示。冻结值是本进程的原启动来源；重启后必须继续从原 immutable config/受控创建来源恢复，不能用任意最新通知重造原创建计划。

初始化仍对本次当前 spec 的角色/目录、当前已加载认证代次、实际 PG 存储身份及前后相同 boot 完整核验，仅创建来源 UUID 改取冻结值。当前配置 UUID 保留官方追踪用途，roles、数据库和存储位置不被错误冻结成旧快照。原配置缺创建 UUID 时仍拒绝补造成功回执。

运行中 configure 在更新 spec/status 前拒绝 tenant/timeline 改绑；启动、Postmaster 启动与内部 reconfigure 也复核冻结存储绑定，不能绕过 HTTP 守卫。合法存储位置/配置 UUID 通知继续允许；换 tenant/timeline 需要新建受控 Compute 身份。未启用 DSGA 的路径保留原行为；没有修改 PG ABI、SQL、版本锁或控制面 wire。

## 必要验证

Mac 新冻结来源单元 1 项通过；新生产 configure Router 改绑守卫 1 项最终通过，并核对拒绝后原 spec/Running 不变；受影响真实 PG 初始化/Router 用例 1 项通过（2.03 秒），新增配置 UUID 变化后仍返回原来源和同一 PG boot 的断言，继续核验当前角色/已加载认证。均 0 fail/ignored，filtered 是定向选择其他用例，不计作本批通过。

首轮 configure 用例漏带已有必填 compute_ctl_config，返回422；补全测试输入后返回预期409。未放宽生产解析规则。失败日志保留在 build/dsga-creation-origin-mac/configure-guard.log；通过与静态日志在 build/dsga-creation-origin-mac2，冻结来源首项通过日志在前一目录。受影响 compute_tools lib/HTTP clippy 通过，保留既有依赖警告。未重复无关测试，未重编未修改的内核/扩展。

复现使用新测试名 frozen_creation_is_distinct_from_current_configuration、managed_configure_rejects_storage_rebinding_before_state_change；真实用例 dsg_hba::tests::native_initialization_observes_original_boot_roles_and_loaded_policy 显式 --ignored --exact，并提供 NEON_TEST_PG_BIN/NEON_TEST_DSG_EXPECTED_SHA=b144a23b2beae7e6d214c094121bf4bbfe13cd3d。

本批不是完整存储通知/暂停唤醒或 Agent 预算链验收；实际 Agent 持久全预算/准入、公开worker、完整排空/最终VM、跨boot恢复等仍继续实现。实际 Linux K8s/RBAC/Service/存储/证书/NeonVM/HugeTLB/物理内存/性能留目标环境验收。仅PG17，不构建镜像、不准备部署、不合并main。
