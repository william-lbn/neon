# PG18 存储发行依赖与真实装载验证

## 发现与原因

2026-11-07，独立 PG18 Compute 初始化时，Pageserver 的回放子进程报告缺少 neon_walredo。候选 Pageserver 的 v18 目录复制了 PG18、neon 与 neon_rmgr，手工组装遗漏了原有 neon_walredo 发行依赖。

原 pgxn/Makefile 的 install-storage 目标包含 neon_rmgr 与 neon_walredo。后续按 PG 大版本生成存储发行目录时，应复用该目标，并将同一 PG_CONFIG 对应的完整安装结果打包。

## 修复与边界

沿冻结的 Neon 365745523144dd02da223e3c8374092d7942dedf 与 PG18 940b25fbf8899edf91781d711639ed7cd28866e9 输入，使用实际 PG18 18.2 头文件补编原 neon_walredo。扩展 ELF SHA256 为 6e87e9695f01f1dbe8862ec6be082cb280da15008064805d60eb26eeef2d25df。

首次构建快照只包含扩展子目录，缺少共享 neon_pgversioncompat.h。保留该失败后补齐同一提交的 pgxn 源码，原扩展编译完成。详细构建日志保存在 118 的 /data/neon-build/validation/PG18-原WAL回放扩展补齐-20261107T0550Z。

补齐后的 Pageserver 镜像为 127.0.0.1:5001/neon-candidate/pageserver@sha256:19a7b31b32c7ef3ec5de766a36a25c3bb225c56f8b982a68e3324b52d6898c1b。118 构建后经 SSH 预载到 worker-117、worker-118、worker-119。自有 neon-pg17-core Helm 第 10 版采用该 digest，原 PG18 Compute 随后从初始化等待进入 Running。正式部署回执包含 PVC UID 与原 PG17 timeline 读回。

## 防止再次漏装

新增 scripts/verify-storage-distribution.sh，在给定准确 digest 的发行镜像内，执行指定 PG 大版本的 postgres --wal-redo。该调用真实装载 WAL 回放扩展，执行环境禁网、只读根盘、限时 30 秒、内存 512 MiB。

实际回归使用同一脚本。旧漏装镜像退出 1，错误明确包含 neon_walredo。修复镜像退出 0。actual-smoke.PUBLIC.json 记录两个结果，日志一并归档。

新发行目录应先执行原 install-storage，再执行此脚本。PG 大版本仅作为发行目录选择输入。Agent、Scheduler、Runner、Proxy 的伸缩合同沿用共同实现。
