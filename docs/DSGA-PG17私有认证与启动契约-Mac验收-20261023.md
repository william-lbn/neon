## 本批实现与不变量

1. **内部管理走私有 peer 通道。** PGDATA 与 dsg_socket 必须归当前服务 UID、
   非符号链接、0700；认证文件原子创建为0600。按实际 OS 用户名映射内部身份，
   cloud_admin 继续无 PG 密码。Rust 管理连接从空 Config 构造单一 Unix socket，
   不继承旧 URL 的 password/hostaddr/options/TCP fallback；Linux vm-monitor/LFC
   使用同一通道。普通业务不得进入内部 SU 白名单。
2. **先 hold，再发布业务认证。** 初始 HBA 只放行内部 peer；主库原子角色应用或
   RO 实际回放核验成功后，普通业务名单走 SCRAM；JWT 名单仅在127.0.0.1/::1
   保留官方受信 local_proxy 的 trust 语义。HBA 本身不验 JWT，此处依赖 Guest
   内本地进程信任边界。其余本地/TCP/physical replication 明确拒绝。HBA 更新
   不会撤销已有会话，不能将此模块当作完整 quiesce。
3. **Postmaster 参数固定认证入口。** 命令行固定 hba_file、ident_file、唯一 socket、
   权限与 group，防止旧备份 auto.conf/include/default trust 覆盖。写配置前先
   验证角色、预算及平台 socket 路径长度，拒绝时保留原文件。非受管路径沿用官方。
4. **确认实际加载，而非只确认发过 SIGHUP。** 每份 HBA 放入随机不存在数据库的
   local cloud_admin 拒绝规则。旧策略会返回库不存在3D000，新策略应返回认证
   拒绝28000；有限期限探测后再核对实际 HBA/ident 路径及正常管理身份。无效
   HBA 的 pg_reload_conf=true 不算成功；失败不发布代理或 Running。文件使用
   同目录 create_new/fsync/rename/目录fsync；替换链接本身，不写入链接目标。
5. **冻结完整启动契约。** 原始7个 DSGB 字段和端口一次捕获；在线配置禁止漂移
   protocol/VM/Compute/boot/M/最低未来Guest/reserve，也禁止切换动态模式。
   独立配置互斥锁串行角色与 hold/publish，不持 state/ApplyContext 跨网络等待。
   新 resize 检查 Running 和当前契约；坏 configure 不得隐藏原实例查询/取消
   身份，更不能人为设为 Running 后绕过检查。
6. **物理备份的运行文件不得成为副本锁。** 仅新 PGDATA 启动前初始化私有目录。
   存在 postmaster.pid、未知条目、链接或错误权限即拒绝并保留；全部验证后只
   清除有限数量的已知 socket/lock。不按源 PID 是否存活猜测副本状态；在线
   hold/publish 从不执行该清理。
7. **端口及角色字面值不得歧义。** 显式选取并冻结唯一端口，拒绝重复、列表、
   冲突、0及溢出，避免 Rust PG 解析器优先尝试默认5432。PG17 HBA 即使加引号
   也将 `/` 前缀编译为正则，故受管角色在改 PGDATA 前拒绝该前缀，防止 `/.*`
   扩大 JWT trust 到 SU。其他已验证引号/Unicode/逗号/反斜线名称仍按字面匹配。
   URI 空格用%20，不能使用 PostgreSQL URI 解析器不还原的+。
