# 真实前台在途与进程生存期登记

沿现有自有V3服务分支增量实现。实际PG源码是Neon的`vendor/postgres-v17`，
不是独立PG副本；Rust pageserver/safekeeper无需为前端消息登记做无关改动。
仅PG17，其他大版本暂缓；功能默认关闭，不合主分支、不构建镜像或部署。

- 独立私有固定槽目录按MaxBackends及辅助进程计费，全部纳入主共享段启动预算。
  不修改Buffer ABI6、PGPROC布局或WAL。每次共享内存重建使用新boot、新关闭门禁。
- `InitProcess`/`InitAuxiliaryProcess`安装退出回调后登记；ProcKill在资源/锁组清理
  后、清空MyProc/归还槽前注销。后台/并行及辅助进程记录真实生存期，未知旧槽
  所有权不能清零伪成功，PANIC交由Postmaster重建，不猜PID存活。
- SocketBackend在官方类型校验后、正文扩张前，以同一status_lock原子检查准入
  并登记。先进入者READING；关闭后普通新工作只走固定缓冲BOUNDED_INPUT。
  Describe可触发缓存计划重验，补齐正文前和执行前门禁。Sync/Close等保留官方清理。
- 真正命令执行后标记EXECUTING；COPY自己的读写/WAL流直到真实命令返回都在此阶段。
  ERROR长跳转不提前清零；事务/Portal/消息清理及Ready刷出后才变IDLE。
- 保留事务独立于读入/丢弃阶段。慢拒绝帧不能隐藏BEGIN/失败事务或扩展协议未Sync事务。
  同一Query内`BEGIN; SELECT观察函数`也不得排除观察者自身。
- 固定五个阶段计数覆盖所有client；按同一次status_lock复制boot/floor/generation/
  门禁及计数。锁内O(1)、不扫描、无内存分配/目录查询/等待/ERROR，不嵌套ProcStructLock。
  可信固定只读管理调用可排除当前观察命令，显式/保留事务不能排除，其他SU工作仍登记。

## 正式接口

独立Native Work API1，不靠PG版本猜能力。Neon扩展1.12正式增量升级安装
`neon_dsg_work_state()`，降级移除；默认撤销PUBLIC，C入口同时核验当前和session
SU，SQL ACL误授也不能越权。旧内核/未升级正式扩展拒绝，不伪造零计数。

Compute API有类型响应逐项校验必填、协议、同一Native实例、阶段总数和事务子集。
`foreground_idle`必须等于关门且无startup/read/execute/保留事务；有界丢弃只说明
不再按正文长度分配，固定连接成本仍需预算。u32计数用u64求和，不能回绕伪零。
固定认证GET `/dsg/v1/work/state`使用原独立观察管理连接，既有VM/Compute/issuer
核验保留；控制面只加入同一固定GET转发白名单。Go SDK用独立观察池及严格解码，
只读结果不能解除resize/准入Pending，不写任何Quiesce/预算/VM回执。
