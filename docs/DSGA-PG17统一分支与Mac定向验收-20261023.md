## 本批PG17复制权限修复

普通业务角色为兼容Neon保留REPLICATION；这也会赋予全实例WAL、备份及物理槽
操作能力，SQL密码列ACL不能保护物理数据。本批在Neon PG17源码增加68行、5个
文件，不另建数据库：

1. physical walsender启动要求内部管理SU；logical startup不能借道执行物理
   BASE_BACKUP、START_REPLICATION、UPLOAD_MANIFEST及相关物理协议。
2. SQL函数与复制协议共用的物理建槽/认领入口做统一检查。认领在ControlLock
   保护槽存在/类型时检查，尚未持spinlock、改active_pid或进入CV等待；ERROR
   沿用PG标准LWLock清理。避免按名字预读后同名槽重建导致TOCTOU。
3. 当前身份和session身份均须为SU；兼顾startup SET ROLE及SQL SECURITY DEFINER，
   不以函数owner或最初认证SU身份单独放行。内部私有通道/HBA仍须独立实现。
4. 业务逻辑槽CREATE/ALTER/DROP与真实COPY逻辑流保留；内部管理的真实物理流/
   备份保留；DSGA关闭时沿用官方。slot-sync读取上游物理槽信息走
   `pg_replication_slots` SQL，timeline-history接收代码明确仅用于物理连接，
   未把正常逻辑槽操作改为管理SU专用。完整failover链仍需后续集成验收。

布局和ABI6未改变；ABI6不能证明旧镜像具备本安全策略，完整来源/版本初始化回执
仍须补齐。既有SU会话与旧不安全实例仍需要受控重建/排空；本检查不证明SQL
WAL读取扩展、所有逻辑插件或全通道认证已经安全。
