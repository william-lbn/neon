# PG18正式WAL redo模块的必要底层适配

本批仅适配PG18实际smgr注册、共享内存及AIO接口；PG17原条件分支保留，未修改PG17内核、发行锁或业务协议。PG18核心仍为27b354b4，运行postgres为9a7d0e16；Neon三模块及libpq18的精确SHA见/data冻结索引。

PG18使用原生smgrregister/name/owns与原同步AIO桥，不伪造文件描述符；独立redo进程按PG18 bootstrap/single-user顺序初始化MaxBackends、PM子进程槽与fast-path，再核算共享内存。向量读写使用对应blocknum+i；非法批量和请求本地FD严格拒绝。

本批5个稳定组件目标：默认加载/CREATE EXTENSION；生产双块向量与边界拒绝；正式WalRedoMain/H/B/P/G/EOF；实际PgAioHandle的新增startreadv完成、回收及错误后同backend恢复；真实PG18 SQL UPDATE产生的WAL经原Apply/Get与真实最终页面逐字节比较。不同run只替换同ID，不累计为额外通过。最后两目标来自89f1d7，原三目标分别来自44bfb3/908887。

ci/pg18_walredo_native_probe.py和ci/pg18_walredo_vectors_probe.c是89f1d7原样测试代码。它们仅在隔离的PG18原生测试容器显式执行，默认目录/opt/pg18和/evidence；将C探针映射为/input/pg18_redo_vector_probe.c，冻结pgxn源码映射为/input/source。探针直接包含冻结的生产inmem_smgr.c，以原PG头编译为/evidence/pg18_redo_vectors.so；不向生产安装此探针。使用同/data运行记录中的明确gcc参数，不增加公共PG ABI。

必须区分：am_wal_redo_postgres实际走LocalBuffer同步smgr路径，驱逐本身不证明startreadv；新增startreadv由私有探针持真实PgAioHandle直接验证。WAL目标为实际PG18原记录/FPI/CRC32C/LSN与原页，测试夹具显式关闭data checksums以比较内存页与落盘页全字节。此为真实模块组件验证，未使用正式Pageserver/Safekeeper18，不代表Root/normal/VM/K8s端到端通过。

全部原失败、未裁剪原日志、源码锁、资源限制及大ELF仍留/data/neon-build/validation。最终小索引：/data/neon-build/validation/pg18-redo-pg18-compat-final-freeze-20261102/receipt.json；原始索引与逐run结果均以精确路径和SHA连接，不提交二进制或复制大日志。

追加精确边界：89的非法batch场景在inmem_startreadv前置门拒绝，证明已分配handle/ResourceOwner的错误清理及同backend后续成功，不冒称本次重测了同步桥内部read_callback的PG_CATCH。AIO完成result=2遵循PG18 smgr成功blocks合同，不是直接OS字节数。
